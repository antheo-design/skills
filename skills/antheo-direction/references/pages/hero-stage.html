How it starts

  1. Install the GitHub app

    Pick the repositories Fallback may read. It needs your deploy events and nothing in your code.

  2. Connect your error tracker

    Sentry, Datadog or Honeycomb, with a read-only key. Fallback learns your normal rate over a week of deploys.

  3. Deploy as you do now

    When a deploy doubles the rate, Fallback redeploys the last good commit and posts the reason in the pull request.

Questions

What if the error rate rises for a reason that is not the deploy?
Fallback compares the deployed version with the one before it on the same traffic. A rise on both is not blamed on the deploy.
Does it roll back database migrations?
No. It redeploys code only, and warns you in the pull request when the bad deploy ran a migration.
Which hosts does it work with?
Vercel, Netlify, Fly.io and any host GitHub Actions deploys to.
