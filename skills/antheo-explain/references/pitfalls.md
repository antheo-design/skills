# Pitfalls: when the reading and the eye disagree

Part of antheo-explain. Open it when a measurement does not match what is on screen, when `inspect.mjs` reports
nothing where something visibly is, or before trusting any value from a page that moves. Each row: what you see,
why, and what to do. Until the row's check has been run, the claim is guessed, not measured.

| Symptom | Cause | What to do |
|---|---|---|
| The value read is the start or end value, not the one seen mid-motion | A computed style is the value at the instant it is read. At rest that is the resting value | Freeze the motion at a known time, then read: `document.getAnimations().forEach((a) => { a.pause(); a.currentTime = 120; })`. Or read the keyframes and timing `inspect.mjs` prints and work out the middle (tag it worked out) |
| A layer is visible but no element has it | It is a pseudo-element: `::before`, `::after`, `::marker`, `::placeholder`, `::selection`. They are not in the DOM, so no element query returns them | `getComputedStyle(el, '::before')`. `inspect.mjs` reads `::before` and `::after` on the element and its children; for the others, read the rule in the DevTools Styles panel |
| The dim layer behind a dialog cannot be found | `::backdrop` exists only while its dialog, popover or fullscreen element is open in the top layer | Open it first, then `getComputedStyle(dialog, '::backdrop')`. Closed, there is nothing to read |
| `getAnimations()` is empty, and it still moves | The motion is not CSS or Web Animations. A script writes styles every frame (`requestAnimationFrame`), or it is drawn in a canvas or WebGL, or it is a video, a Lottie file or SVG `<animate>` | Look for a `style` attribute that changes between two reads 100ms apart, a `canvas` or `video` under MEDIA, and the libraries the page loads. Sample the box or transform every frame for one second and report the timing as worked out. What is inside a canvas is guessed |
| An animation is listed with no duration in ms | It is scroll-driven (`animation-timeline`): progress follows scroll position, not time | Report the scroll range it runs over, not a duration. Scroll to two positions and read at each |
| Class names like `css-1q2w3e`, `_a1b2`, or thirty utility classes on one element; wrappers nested five deep | What ships is compiled and minified. Names and nesting are the build's output, not the author's source | Describe by role and by what it does, never by class name. A framework named from a marker (`__NEXT_DATA__`, `data-v-…`) is worked out; the authors' component names and file layout are not knowable. If a public source map exists, read that |
| The value differs from the person's screenshot | It depends on the viewport width (media queries), the container width (container queries), the theme, the pointer (`hover: hover`), reduced motion, or the pixel ratio | Measure at the width and theme where the effect shows (`--width`, `--dark`). State both with every value. Read at two widths before calling a value fixed; for `clamp()` or `vw`, report the formula from the stylesheet |
| The hover, focus, pressed or open look cannot be read | The state is not applied while a script reads it | Put the page in the state for real (hover with the pointer, DevTools "force state", open the menu), then read. A value from the resting state is not the hover value |
| A sticky bar, a fading header, a progress line read differently each time | The value depends on scroll position | Read at the top, at one screen down and at the end, and report all three |
| The selector matches nothing, and the element is on screen | It is inside a shadow root or an iframe. Neither is reached by a query from the page | Open shadow root: `host.shadowRoot.querySelector(...)`. Closed shadow root: not readable, say so. Iframe: open the frame's own URL as a page; a cross-origin frame cannot be read from outside. `inspect.mjs` lists iframes under MEDIA and does not go inside |
| From a video or GIF it looks like one layer | A recording flattens the stack. A blur can be a live `backdrop-filter`, a blurred picture or a second video. Compression smears edges, and a GIF's 256 colours band gradients and drop soft shadows | Step frame by frame. Look for two things that move at different speeds, an edge that stays sharp while what is behind it softens, and anything that does not reflow when the content changes. Everything stays worked out or guessed |
| Durations from a video look like 133ms, 167ms, 200ms | The frame rate sets the smallest step: 33ms at 30fps, 17ms at 60fps | Count frames, give a range ("about 6 frames at 30fps: 170 to 230ms"), and never an exact curve. Easing is "fast then slow" (worked out), not a `cubic-bezier` |
| The colour read is not the colour seen | The element's colour has alpha, or sits under a blend, a filter or an overlay. The eye sees the composite | Report both: the declared colour (measured) and the pixel from a screenshot at that point (measured, of the composite) |
| `font-family` names a face that is not the one drawn | Computed `font-family` is the whole fallback list. The first name may have failed to load | DevTools: Computed, "Rendered Fonts". Or the `fonts loaded` line of `inspect.mjs --site` |
| The look comes from nowhere: the element has no transform, opacity or filter | An ancestor has it. A transform, opacity, filter or mask on a parent changes everything inside | Read the `parent` lines `inspect.mjs` prints, up to the first stacking context |

When none of these explains it, say what was read, what was seen, and that they disagree. That is a finding, not a
gap to paper over.
